# 条件与循环

如果程序只能从头到尾执行固定动作，它很难处理现实中的变化。条件让程序根据情况选择路径，循环让一段操作针对多个对象或多次状态变化重复进行。

## 条件描述执行哪一条路径

```python
pages_read = 48
total_pages = 200

if pages_read >= total_pages:
    message = "已读完"
else:
    message = "阅读中"

print(message)
```

这里输出 `阅读中`。程序先计算比较表达式，再决定执行哪一组赋值语句（若需要超过两个分支，Python 会用 `elif` 连接中间条件）。Python 用缩进（通常 4 个空格）表示语句属于哪个分支，从网页或聊天窗口复制代码时若缩进错乱或混用 Tab 与空格，会触发 `IndentationError`；其他语言如 JavaScript 则常采用花括号 `{ ... }`。

注意 `=` 和 `==` 的区别：在这些 Python 示例里，前者用于赋值，后者用于比较相等（在 JavaScript 中则通常使用严格相等 `===`，避免隐式类型转换）。数学书里的等号与程序语句的角色不完全相同。

条件也可以用 `and`（同时满足）、`or`（满足其一）、`not`（取反）组合。例如，某个输入既要是非负数，又要不超过总页数（`pages_read >= 0 and pages_read <= total_pages`）。要写出正确的组合，首先必须把规则想清楚。代码语法并不会代替人决定“总页数未知时应该怎么办”。

## 边界往往比普通情况更容易被忽略

上面的片段只演示如何选择分支，并没有声称它是一套完整的进度规则。如果 `total_pages` 是 0，或者 `pages_read` 是负数，就需要额外规定该如何处理。

这不是要求所有短示例都加入大量检查，而是要分清示例在说明什么。阅读 AI 生成的代码时，也应留意它是否把一个只适用于普通情况的演示，当成了覆盖全部输入的实现。

## 循环重复的是规则

```python
daily_pages = [12, 8, 20]
total = 0

for pages in daily_pages:
    total = total + pages

print(total)
```

输出 `40`。每一轮，`pages` 对应列表中的下一项，程序把它加到累计结果里。初始化 `total = 0` 放在循环外，意味着从一个初始值开始累计；如果每轮都把它重新设为 0，含义就不同了。在 AI 生成的代码中，还常看到用 `range(n)` 生成从 `0` 到 `n - 1` 的整数序列（左闭右开，不包含 `n`），或用 `break` 提前跳出循环、用 `continue` 跳过当前这一轮。

这里可以看到三件互相配合的事：要遍历的数据、每轮执行的操作，以及跨轮保留的状态。很多看起来不同的程序，都可以从这三个角度读懂。

## 按条件持续进行

另一类循环根据条件决定是否继续，例如“还有未处理的记录就继续”。它需要让状态有机会发生变化，否则可能一直无法结束。

```python
remaining = 3

while remaining > 0:
    print(remaining)
    remaining = remaining - 1
```

这段代码依次输出 `3`、`2`、`1`。最后一行改变了下一次检查时的状态。如果忘记这一步，条件会一直为真。

也有程序本来就需要长期运行，例如等待新的网络请求。持续运行本身不是错误；要看它是否按预期等待和处理工作，能否合理停止，以及是否无意义地消耗资源。

## 阅读流程比逐字翻译更重要

面对一段较长的代码，可以先找出判断点、重复范围和会变化的状态，再看每个细节。例如，某条提示始终不出现，可能是条件从来不满足，也可能是程序在到达那里之前已经返回或报错。

让 AI 解释代码时，可以要求它按一个具体输入追踪分支和每轮状态。这样得到的是可以与代码核对的执行过程，而不是把每一行换一种自然语言说法。

> [!TIP]
> **实战提示**：当某段分支代码“死活不执行”或循环停不下来时，可以让 AI **用一个具体输入值（特别是 `0`、空列表、负数等边界值）逐行追踪每轮循环的变量变化。**
