# 文件、目录、路径与权限

AI 让你“把配置文件放在项目根目录”。如果还不清楚目录和路径的关系，这句话就很难执行。先看一组很普通的文件：

```text
reading-notes/
├── README.md
├── app/
│   └── main.py
└── data/
    └── notes.txt
```

这里的 `reading-notes` 是我们选作项目起点的目录。`app` 和 `data` 是它下面的子目录，其他几项是文件。这个结构只是一个示例，不代表所有项目都必须这样组织。

## 文件除了内容，还有名字与属性

文件包含数据，也带有大小、时间、访问权限等相关信息。文件名帮助人和程序找到它，目录则把这些名字组织在一定的层次中。

`notes.txt` 的 `.txt` 是扩展名，常用于提示内容类型和选择打开它的程序。扩展名不是格式转换器：改成 `notes.jpg`，里面的文字也不会变成图片。不同系统和应用识别类型的方式还有其他细节，不能只靠文件名判断一份内容能否被正确读取。

有些界面默认隐藏常见扩展名。看起来叫 `notes.txt` 的文件，完整名称可能实际是 `notes.txt.txt`。这会让“文件存在”和“程序按这个名字找不到文件”同时成立。

## 路径把名字放回具体位置

不同目录下可以有同名文件。路径通过父子关系描述位置，让程序区分它们。

Windows 中的绝对路径可能是 `C:\work\reading-notes\data\notes.txt`。在常见的 macOS 或 Linux 环境中，则可能是 `/home/lin/reading-notes/data/notes.txt`。绝对路径从相应文件系统的明确起点描述位置。

相对路径需要一个参照位置。假设当前工作目录是 `reading-notes`，那么 `data/notes.txt` 指向图中的笔记文件。如果当前工作目录改成 `reading-notes/app`，同样的文字就会尝试指向 `app` 下面的 `data`，那可能不是你想找的位置。

| 表达 | 在常见文件路径语境中的含义 |
| --- | --- |
| `.` | 当前目录 |
| `..` | 上一级目录 |
| `data/notes.txt` | 从参照目录进入 data，再找到 notes.txt |
| `../data/notes.txt` | 先返回上一级，再进入 data |

这里用斜杠展示结构；具体工具接受哪种分隔符，需要看它的规则。Windows 路径、网页地址和语言中的模块路径也不能仅凭外形当成同一种东西。

## “当前目录”属于谁

程序运行时通常带有工作目录，终端里的命令也有其当前所在位置。你在资源管理器里打开了一个文件夹，不代表所有已经打开的终端或程序都会同步切换到那里。

更容易混淆的是：程序文件的位置，未必等于程序运行时的工作目录。有的工具按工作目录解析相对路径，有的配置项按配置文件所在目录解释，有的又有自己的约定。遇到找不到文件，应该先确认**哪段代码、按什么规则、以哪里为参照**去寻找它。

这也是为什么把整个项目发给别人后，一段写死在自己电脑上的绝对路径可能失效。项目内可复用的关系通常更适合通过相对位置和明确约定表达；真正依赖机器环境的路径，则需要适当配置。

## 大小写、隐藏文件与链接

`Notes.txt` 和 `notes.txt` 是否是同一个文件名，与文件系统及其配置有关。项目在不同环境中运行时，依赖模糊的大小写匹配可能暴露问题。

以点开头的名字，例如 `.settings`，在一些环境中用来表示隐藏项；“隐藏”主要影响显示方式，并不等于内容被加密。文件系统还可能允许一个名字通过链接指向另一个位置，所以目录树是很有用的基本模型，但不是全部实现细节。

作为读者，先掌握最常见的树形组织已经足够解释许多现象。遇到特殊路径，再进一步查明实际规则。

## 权限决定能做什么

知道文件在哪里，不代表当前运行身份可以读取或修改它。系统会根据用户、用户组、文件属性或访问控制规则等信息决定是否允许某项操作。

“找不到文件”和“没有权限访问”指向不同的问题。前者可能与路径有关，后者可能需要检查运行身份和权限设置。把所有问题都归结为“代码错了”，容易让 AI 修改本来正常的逻辑。

权限还有具体操作之分：能够读取一个文件，不必然能够改写它；能够在某个目录查看内容，也不必然能够创建文件。理解报错涉及的操作，比直接给所有对象更大的权限更有针对性。

下次看到“项目根目录”“相对路径”或“文件不存在”，可以把实际目录树和程序的工作目录放在一起看。它们往往能把一句模糊的错误，变成一个明确的位置问题。
