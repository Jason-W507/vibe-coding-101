# 文件、目录、路径与权限

AI 让你“把配置文件放在项目根目录”。如果还不清楚目录和路径的关系，这句话就很难执行。先看一组很普通的文件：

```text
reading-notes/
├── README.md
├── app/
│   └── main.py
└── data/
    └── notes.txt
```

这里的 `reading-notes` 是我们选作项目起点的目录（也就是图形界面里常说的“文件夹”，项目的最顶层文件夹通常称为**项目根目录**）。`app` 和 `data` 是它下面的子目录，其他几项是文件。这个结构只是一个示例，不代表所有项目都必须这样组织。

## 文件除了内容，还有名字与属性

文件包含数据，也带有大小、时间、访问权限等相关信息。文件名帮助人和程序找到它，目录则把这些名字组织在一定的层次中。

`notes.txt` 的 `.txt` 是扩展名，常用于提示内容类型和选择打开它的程序。扩展名不是格式转换器：改成 `notes.jpg`，里面的文字也不会变成图片。不同系统和应用识别类型的方式还有其他细节，不能只靠文件名判断一份内容能否被正确读取。

有些界面默认隐藏常见扩展名。看起来叫 `notes.txt` 的文件，完整名称可能实际是 `notes.txt.txt`。这会让“文件存在”和“程序按这个名字找不到文件”同时成立。排查时建议打开扩展名显示（Windows 11 资源管理器点击“查看 → 显示 → 文件扩展名”；macOS 访达在“设置 → 高级”中勾选“显示所有文件扩展名”）。

## 路径把名字放回具体位置

不同目录下可以有同名文件。路径通过父子关系描述位置，让程序区分它们。

Windows 中的绝对路径从盘符开始，例如 `C:\work\reading-notes\data\notes.txt`。macOS 与 Linux 则从唯一根目录 `/` 开始：macOS 用户目录通常是 `/Users/lin/reading-notes/data/notes.txt`，Linux 常见为 `/home/lin/reading-notes/data/notes.txt`（在 Bash、Zsh 和 PowerShell 中，波浪号 `~` 常用来简写当前用户的主目录，但传统 Windows `cmd` 不识别 `~`）。绝对路径从相应文件系统的明确起点描述位置。

相对路径需要一个参照位置。假设当前工作目录是 `reading-notes`，那么 `data/notes.txt` 指向图中的笔记文件。如果当前工作目录改成 `reading-notes/app`，同样的文字就会尝试指向 `app` 下面的 `data`，那可能不是你想找的位置。

| 表达 | 在常见文件路径语境中的含义 |
| --- | --- |
| `.` | 当前目录 |
| `..` | 上一级目录 |
| `data/notes.txt` | 从参照目录进入 data，再找到 notes.txt |
| `../data/notes.txt` | 先返回上一级，再进入 data |

Windows 传统使用反斜杠 `\` 作路径分隔符（但多数现代 Windows 工具和 PowerShell 也接受正斜杠 `/`），macOS 与 Linux 则使用 `/`。需要注意的是，在 Python、JavaScript 等许多编程语言的普通字符串里，`\` 是转义符——直接写 `"C:\new\notes.txt"` 会把 `\n` 当成换行符导致路径出错，代码中通常应使用 `/`、双反斜杠 `\\` 或专用路径库（如 Python 的 `pathlib`）。此外，尽量把开发项目放在纯英文、无空格、且不被网盘（如 OneDrive）实时同步锁定的路径下（例如 `D:\projects\reading-notes`），能避开大量因中文用户名、空格未加引号或文件占用引起的报错。

## “当前目录”属于谁

程序运行时通常带有工作目录，终端里的命令也有其当前所在位置。你在资源管理器里打开了一个文件夹，不代表所有已经打开的终端或程序都会同步切换到那里。

更容易混淆的是：程序文件的位置，未必等于程序运行时的工作目录。有的工具按工作目录解析相对路径，有的配置项按配置文件所在目录解释，有的又有自己的约定。遇到找不到文件，应该先确认**哪段代码、按什么规则、以哪里为参照**去寻找它。

这也是为什么把整个项目发给别人后，一段写死在自己电脑上的绝对路径可能失效。项目内可复用的关系通常更适合通过相对位置和明确约定表达；真正依赖机器环境的路径，则需要适当配置。

## 大小写、隐藏文件与链接

`Notes.txt` 和 `notes.txt` 是否是同一个文件名，取决于文件系统：Windows（NTFS）和 macOS（APFS 默认配置）通常不区分大小写，而 Linux（如 ext4）严格区分大小写。因此，代码中把 `Notes.txt` 写成 `notes.txt` 在本地电脑上可能正常，部署到 Linux 服务器后就会报“找不到文件”。

以点开头的名字（如存放环境变量的 `.env`、Git 忽略规则 `.gitignore`、版本库目录 `.git`），在 macOS 和 Linux 中默认隐藏，在 Windows 中也可能因隐藏属性而不显示（macOS 访达可按 `Cmd + Shift + .` 切换显示，Windows 可勾选“查看 → 显示 → 隐藏的项目”）；“隐藏”主要影响显示方式，并不等于内容被加密。文件系统还可能允许一个名字通过符号链接（symlink）指向另一个位置，所以目录树是很有用的基本模型，但不是全部实现细节。

作为读者，先掌握最常见的树形组织已经足够解释许多现象。遇到特殊路径，再进一步查明实际规则。

## 权限决定能做什么

知道文件在哪里，不代表当前运行身份可以读取、修改或执行它。在 macOS 或 Linux 上，缺少权限常报 `Permission denied`（例如刚下载的脚本需要 `chmod +x` 赋予可执行权限，但不应为了省事随意对项目使用 `sudo` 或 `chmod 777`）；在 Windows 上，除了管理员权限（UAC）限制外，还常遇到“另一个程序正在使用此文件，进程无法访问”——这通常是因为该文件或目录正被编辑器、未关闭的后台终端进程或同步软件锁定，并非路径写错。

“找不到文件”和“没有权限访问”指向不同的问题。前者可能与路径有关，后者可能需要检查运行身份和权限设置。把所有问题都归结为“代码错了”，容易让 AI 修改本来正常的逻辑。

权限还有具体操作之分：能够读取一个文件，不必然能够改写它；能够在某个目录查看内容，也不必然能够创建文件。理解报错涉及的操作，比直接给所有对象更大的权限更有针对性。

下次看到“项目根目录”“相对路径”或“文件不存在”，可以把实际目录树和程序的工作目录放在一起看。它们往往能把一句模糊的错误，变成一个明确的位置问题。

> [!TIP]
> **实战提示**：遇到 `FileNotFoundError` 时，先别急着让 AI 重写代码，先核对三件事：**文件真实扩展名有没有被系统隐藏？当前终端的工作目录在哪里？代码里的相对路径是以哪里为起点？**
