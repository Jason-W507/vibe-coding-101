# 常见数据结构各有什么用

同一批信息可以有不同组织方式。你可以按顺序保存书名，也可以按编号查找记录，还可以只关心某个标签是否出现过。数据结构帮助程序把这些关系表达出来，也影响操作的成本。

## 顺序：列表与数组

需要保留先后关系时，列表是很自然的概念。第一个元素、第二个元素和“在某项后面插入”都有明确意义。

数组是一种常见的实现思路：元素按一定方式连续组织，使按位置访问具有直接的计算规则。动态数组可以在需要时扩大容量，但扩容可能需要搬移内容。保持顺序地在中间插入，也可能影响后面的许多元素。

语言里的“列表”名称描述了可用的抽象，不必然代表同一种底层结构。另一个常见实现是链表：各节点通过链接联系起来。已经定位到合适节点、且掌握必要邻接信息时，修改链接可以很直接；如果还要先找到那个节点，查找过程同样需要成本。

## 按名字找：映射

映射建立键与值之间的对应关系。例如，用一本书的编号找到它的标题：

```python
titles = {101: "计算机基础", 205: "软件开发入门"}
print(titles[205])
```

输出 `软件开发入门`。这里表达的是“给我这个键对应的值”，而不是“给我第 205 个位置”。选择稳定的键，也能避免仅用可能重名的标题区分记录。

哈希表是实现映射的一种常见方法，通过计算把键引向适合查找的位置。不同键仍可能发生碰撞，需要进一步处理。另一些映射可能采用树结构等实现，所以抽象能力与具体实现应分开理解。

## 只关心是否存在：集合

如果要记录“这本书有哪些标签”，并且同一标签只需要出现一次，集合更贴近这个意思。

```python
tags = {"入门", "计算机", "入门"}
print(len(tags))
print("计算机" in tags)
```

输出依次为 `2` 和 `True`。示例没有把集合当成有固定显示顺序的列表；它突出的是去重和成员关系。

## 处理顺序：栈与队列

栈的常见规则是后放入的先取出，可用来理解一部分撤销记录或嵌套处理过程。队列的常见规则是先进入的先被取出，可用来组织等待处理的工作。

这些规则不意味着所有真实系统都严格采用同一种次序。例如，任务系统还可能安排优先级。先把基本结构的规则说清楚，才能进一步理解改变规则带来的行为。

数据结构里的栈与内存管理中的调用栈存在联系，但不要把所有叫“栈”的东西都当成某一块固定内存。算法中还有名为“堆”的结构，它与堆内存也不是同一个概念。

## 层次关系：树

目录的层次是理解树的直观入口：从根逐级到子节点。分类、语法结构和某些查找组织也可以采用树。真实文件系统存在链接等额外机制，因此目录只是帮助理解层次的例子。

如果关系不适合“一个节点只有一个上级”这样的树形组织，就可能需要更一般的图。项目依赖、道路连接等场景会用到这种认识。

## 选择结构，先看要做什么

需要按序遍历、按键查找、频繁插入、去重还是表达层次，会影响选择。某种结构适合一个操作，不代表它对所有操作都同样合适。

这些取舍的细节可进一步阅读作者公开的 [Open Data Structures](https://opendatastructures.org/ods-python/)。在入门阶段，先能说清“这组数据是什么关系、程序主要怎样使用它”，就已经能帮助你理解 AI 为什么选择某个容器，或者判断它的选择是否贴合实际问题。
