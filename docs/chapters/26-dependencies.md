# 依赖、包管理、库与框架

程序通常不会从最底层重新实现所有能力。处理图片、解析格式、建立网络服务等工作，可以使用其他人提供的代码。这些被项目需要的内容，构成了依赖关系。

## 库和框架帮助组织不同层面的工作

**库**提供可调用的能力，程序在需要时使用它。**框架**通常进一步规定应用的一部分组织与执行方式，让开发者按照其约定提供代码。两者边界在实际命名中并不总是绝对清晰。

理解一个工具时，可以观察谁安排主要流程、你需要提供哪些接口，以及它替你管理了什么。无论名称叫库还是框架，底层仍然需要处理程序、数据、文件和运行环境等问题。

使用框架也不会自动使需求明确或代码正确。它减少了一些重复工作，同时引入自己的约定和需要学习的内容。

## 包与包管理工具

包是分发代码或其他内容的一种组织单位。包管理工具负责按相应生态的规则查找、获取、安装或管理这些内容。

一个项目直接依赖某个包，这个包又依赖其他包，形成**传递依赖**。因此，自己只写了几行代码，却需要准备较多依赖，并不一定反常。项目实际需要理解和维护的外部关系，也不只停留在直接声明的那几个名字上。

依赖声明文件（如 Node.js 的 `package.json`、Python 的 `pyproject.toml` 或 `requirements.txt`）描述项目需要什么；而**锁定文件**（如 `package-lock.json`、`pnpm-lock.yaml`、`poetry.lock`、`uv.lock`）则精确记录解析出来的每一个直接与传递依赖的具体版本号、下载地址与内容校验哈希，用来确保其他机器或部署环境安装出**完全一致**的依赖组合。应用项目通常应将 lock 文件提交到 Git，且不要手工编辑它。

## 版本号表达变化，但不是绝对保证

版本帮助区分同一个依赖在不同时间的内容。更新可能增加能力、修复问题，也可能改变接口或运行要求。

许多生态采用**语义化版本（SemVer，形如 `主版本.次版本.修订号`，如 `2.4.1`）**约定：主版本号升级代表可能存在不兼容修改，次版本号代表向下兼容的功能新增，修订号代表向下兼容的问题修正（而 `0.x.y` 初始开发阶段可能随时改变接口）。在 `package.json` 中常见的 `^1.2.3` 表示允许升级到 `<2.0.0` 的最新兼容版本，`~1.2.3` 表示允许升级到 `<1.3.0`；Python 中则常见 `==1.2.3`（固定版本）或 `>=1.2,<2.0`。但版本号只是作者的声明，实际是否兼容仍需通过运行测试确认。

这也是为什么依赖更新通常需要查看变更并运行相应检查。版本管理中的“代码没变”，可能只是指自有源码没变；依赖变化仍然可以改变程序的实际行为。

## 环境隔离解决相互牵连

两个项目可能需要不同版本的同一工具或包。如果它们完全共享一份可变环境，修改其中一个项目的依赖可能影响另一个。

不同生态提供虚拟环境、项目局部依赖或其他隔离机制，让项目尽量拥有明确的依赖边界。例如 Node.js 的 `npm install` 默认把包安装在当前项目的 `node_modules/` 下；而 Python 则常在项目目录下创建虚拟环境（如运行 `python -m venv .venv`，激活后再用 `python -m pip install ...` 安装，这样能确保 `pip` 与当前 `python` 指向同一套环境）。隔离与“把程序放进一个不同文件夹”不完全相同，需要看执行时实际选择了哪份解释器、包和配置。

## 警惕依赖安全与“AI 包名幻觉”

安装第三方包本质上是在你的电脑或服务器上信任并执行别人写的代码（许多包管理器在安装阶段就可能运行脚本）。使用 AI 辅助编程时，尤其要注意两类供应链风险：
- **仿冒包（Typosquatting）**：恶意包故意起一个与知名库差一个字母的名字；
- **包名幻觉抢注（Slopsquatting）**：语言模型有时会自信地编造出一个实际上并不存在的包名，而攻击者会专门监测模型常编造的假名字并抢先在 PyPI / npm 上注册同名恶意包。

因此，当 AI 建议安装一个陌生的第三方包时，**不要盲目自动执行安装命令**：应先到官方仓库（`pypi.org` 或 `npmjs.com`）核对这个包是否真实存在、下载量与维护历史是否正常、是不是标准库本来就有的功能，并可使用 `npm audit` 或 `pip-audit` 检查已知漏洞。

## 安装成功与运行成功还差一步

取得了包，不代表当前启动程序的环境就会使用它。常见的差异包括使用了另一份语言运行时、安装位置不在查找范围内、操作系统或处理器架构不匹配，以及缺少额外系统条件。

面对 AI 给出的“再安装一次”建议，可以先确认它试图补齐哪项依赖、当前命令使用的是哪个环境，以及安装后会改变什么。理解依赖关系，比不断叠加安装步骤更有助于解释问题。
