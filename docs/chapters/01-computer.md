# CPU、内存、磁盘与操作系统

在电脑里保存一份文档，再打开它修改，是非常普通的操作。这个过程中至少有三个不同的问题：文档放在哪里，编辑时的信息放在哪里，以及是谁让修改真正发生。它们分别把我们引向存储、内存和处理器。

## 用一次编辑过程认识几个组成部分

假设你双击一份已经保存的笔记。操作系统根据文件关联找到合适的编辑器，启动它或把文件交给已经运行的编辑器。编辑器读取文件内容，把正在编辑的信息组织在内存中，显示到窗口里。你输入一个字，程序更新自己的数据，再让界面显示新的内容。

点击保存后，程序通过操作系统请求把需要保留的数据写入文件。为了提高效率，现代系统常先把数据写进内存缓存，再安排实际的磁盘写入。这也是为什么拔掉 U 盘前需要“安全弹出”：如果缓存里的数据还没真正落盘就断开连接，文件就可能损坏或丢失。想亲眼观察 CPU、内存和磁盘的实时占用，可以在 Windows 按 `Ctrl + Shift + Esc` 打开“任务管理器”，在 macOS 打开“活动监视器”，或在 Linux 运行 `top` / `htop`。

| 组成部分 | 主要职责 | 在这个例子里 |
| --- | --- | --- |
| CPU，也叫处理器 | 执行指令，进行运算、判断和数据操作 | 执行编辑器和系统需要完成的步骤 |
| 内存，通常指 RAM | 容纳程序运行中需要访问的代码和数据 | 保存正在编辑的内容、光标位置等状态 |
| 长期存储，如 SSD | 在没有持续供电时仍保留已写入的数据 | 保存编辑器文件和笔记文件 |
| 操作系统 | 管理运行、资源、文件、设备和权限 | 启动编辑器，协调读取、显示及保存 |

“硬盘”在日常表达中常被用来泛指长期存储。今天常见的 SSD 没有机械盘片。本教程在讨论职责时使用“存储”或“磁盘”，并不要求它一定采用某一种物理结构。

## CPU 怎样让程序产生作用

CPU 能够执行其指令体系规定的操作，例如进行计算、读写某个位置的数据、比较两个值，或者转到另一段指令继续执行。一个复杂的功能，需要很多这样的步骤组合起来。

“把这一段文字变成蓝色”是应用层的描述。底层可能涉及找到文字对象、更新样式信息、重新计算显示内容和向图形系统提交结果。处理器并没有预先理解“这是一篇笔记”的意义；软件把人的意图组织成了可执行的处理过程。

处理器内部还有寄存器、缓存以及多种提高执行效率的机制。有些任务会交给 GPU 等适合特定计算方式的硬件。暂时不必把它们都展开：这里需要建立的是，**运行中的功能需要实际的执行资源**。后文会进一步解释指令和执行状态。

## 为什么不能只靠磁盘

CPU 需要频繁访问正在使用的数据。主内存承担运行时的工作空间，它与长期存储有两个核心差别：**访问速度相差悬殊**（内存读写通常在百纳秒级，常见 SSD 随机访问在几十到上百微秒级，相差上百到上千倍），且 **CPU 不能直接对磁盘文件中的数据做运算**，待处理的数据必须先装入内存。

这并不意味着程序每次启动都把整个文件或所有数据一次性复制到内存。现代系统会按需要装入部分内容，也会重复利用已经缓存的信息。一个很大的文件，可能只被分段处理。

常见的 RAM 具有易失性：供电中断后，不能指望它继续保留原来的内容。更重要的是，**即使不断电，只要进程结束（如关闭窗口、关掉终端、程序崩溃或刷新网页），操作系统也会立刻回收该次运行占用的内存**（见[第 04 篇](04-programs-processes.md)、[第 05 篇](05-memory.md)）。因此，输入到编辑器里但尚未持久保存的信息，和已经写入文件的信息，处于不同的状态。某些应用有自动保存或恢复功能，是因为它们另外进行了保存工作。[《Operating Systems: Three Easy Pieces》的导论](https://pages.cs.wisc.edu/~remzi/OSTEP/intro.pdf)从资源管理和持久保存的角度介绍了这些区别。

“内存还有空间”和“磁盘还有空间”也不能相互替代。一张图片文件可能经过压缩，读入后要展开成更大的像素数据；程序还会建立用于编辑、撤销和显示的其他数据。因此，文件大小不等于处理这个文件时的全部内存占用。

## 操作系统为什么必不可少

一台电脑经常同时运行浏览器、编辑器、音乐播放器和后台服务。它们不能都任意占有 CPU、覆盖其他程序的数据，或者绕过文件权限。操作系统和硬件一起建立了管理和隔离机制。

系统决定可运行的任务何时获得处理器，管理程序可以使用的内存范围，组织文件与目录，并提供访问设备的方式。应用通常通过系统提供的接口请求这些能力，而不必自己实现整套磁盘或键盘控制逻辑。

操作系统中直接承担核心管理职责的部分称为**内核**。桌面、窗口外观和设置面板则属于人更容易看见的系统组件。它们关系密切，但不能把操作系统仅理解成“桌面长什么样”。

```mermaid
flowchart LR
    A[编辑器：请求读取笔记] --> B[操作系统：检查与组织访问]
    B --> C[存储设备：提供文件数据]
    C --> D[内存中的编辑状态]
    D --> E[处理与显示]
    E -->|保存请求| B
```

图中省略了缓存、驱动和具体输入输出过程，重点是职责如何配合。

## 安装、启动、关闭和卸载分别改变什么

安装通常把软件所需的文件和配置放到合适的位置。启动使相应的程序进入运行状态。关闭应用通常结束相应的交互活动并释放资源，但某些后台任务可能继续运行。卸载则移除已安装的软件及相关内容，是否同时删除用户数据取决于具体软件的设计。

这能解释许多常见现象：已经安装的软件可以暂时不运行；正在运行的程序会占用资源；关闭窗口后文件仍然存在；删除快捷方式也不等于删除软件本体。

看到“电脑变慢”时，原因也可能处在不同位置。程序可能忙于计算（CPU 占用高），可能在等待磁盘读写或网络响应，可能因为内存吃紧而频繁在内存与磁盘交换空间之间搬运数据（见[第 05 篇](05-memory.md)），也可能在等待另一项操作。仅凭“慢”这个感觉，不能直接判断一定需要更快的 CPU。

当 AI 说“程序已经生成好了”时，可以把这句话放回这些层次：文件是否已经保存，运行它所需的环境是否存在，程序是否真正启动，以及数据是否写到了预期的位置。这些问题比仅观察一个窗口是否出现，更接近软件实际发生的过程。
