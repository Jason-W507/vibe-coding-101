# 数字、文字、图片怎样成为数据

电脑能处理文字、照片、音乐和代码，但存储设备并不为这些内容各准备一种专用材料。它们最终都需要用可区分的物理状态表示，并按照约定解释。数字表示与编码，就是从这些状态走向有意义内容的桥梁。

## 比特和字节记录的是多少种可能

一个**比特**，英文 bit，可以取两个值，通常写成 0 和 1。这里的 0 和 1 是对状态的抽象表示，具体硬件如何实现这些状态，会因设备而异。

把多个比特组合起来，可以表示更多可能。两个比特有 `00`、`01`、`10`、`11` 四种组合；八个比特有 256 种组合。现代通用计算机中，一个**字节**，英文 byte，通常由八个比特组成。

如果把一个字节解释成无符号整数，可以表示 0 到 255。假如需要负数、更大的整数或者小数，就要选择相应的编码规则与存储空间。位数和规则一起决定能够表示什么。

这也解释了文件大小和内容含义为什么是两件事：十个字节告诉你有多少存储单位，却没有告诉你这些单位应被当成文字、像素还是某种程序指令。

## 同一组位，可以有不同含义

`01000001` 按二进制无符号整数解释是 65。按照 ASCII 中相应字符的约定，它也可以表示字母 `A`。如果它出现在图片数据的某个位置，含义又取决于图片格式。

因此，不能仅看见一串字节就知道它是什么。读取方需要格式、类型或其他上下文。文件扩展名可以提供线索，但真正的解释还要遵守内容的格式规则。

编码就是把某类信息与某种表示对应起来的约定。表示方法一致，双方才能交换信息；用不匹配的规则读取数据，就可能出现乱码或解析错误。

## Unicode 与 UTF-8 各负责什么

文字不仅有英文字母，还有汉字、标点、符号和表情。Unicode 为字符等内容分配称为**码点**的编号，并规定相关文本处理规则。码点常写成 `U+` 加十六进制数字的形式，例如 `中` 的码点是 `U+4E2D`。

这些编号还需要保存成实际字节。UTF-8 是一种编码方式：不同的 Unicode 标量值会编码成一到四个字节。以三个常见字符为例：

| 文本 | 码点 | UTF-8 字节，十六进制表示 |
| --- | --- | --- |
| A | U+0041 | 41 |
| 中 | U+4E2D | E4 B8 AD |
| 🙂 | U+1F642 | F0 9F 99 82 |

于是，文本 `A中🙂` 在 UTF-8 中占八个字节，未计文件中可能存在的其他内容。这组字节可由编码工具直接验证。Unicode 与 UTF 编码的关系可参阅 [Unicode 官方 FAQ](https://www.unicode.org/faq/utf_bom.html)。

“看起来有几个字”和“需要几个字节”显然不同。更进一步，一个视觉上的字符还可能由多个码点组合而成，例如带组合附加符号的字母或某些表情序列。因此，讨论“字符串长度”时，需要知道所用工具在数的是字节、码点、编码单元，还是用户看到的文本单元。

## 图片怎样表示

可以先从一个简化的彩色位图理解。图片由像素组成，每个像素记录颜色信息。某些表示方式用红、绿、蓝三个分量描述颜色；如果每个分量用一个字节，那么一个像素的这部分数据就占三个字节。

一幅 100 × 100 像素、每个像素三个字节的未压缩 RGB 图像，单看像素数组需要 30,000 字节。实际文件还可能包含尺寸、色彩信息等元数据，也可能采用压缩，因此不能拿这个数字直接推断某个 PNG 或 JPEG 文件的大小。

**文件格式**不仅说明数据怎样排列，还可能规定压缩、校验和其他结构。把 `photo.jpg` 改名为 `photo.png`，不会自动重排或转换内部字节。文件名变了，编码方式没有因此改变。

## 文件压缩、编码与加密有什么区别

压缩试图利用数据中的规律减少表示所需的空间；某些压缩保留全部信息，某些会舍弃部分信息以换取更小体积。编码解决表示和交换问题。加密则让没有相应密钥的人难以获得原来的内容。

这些操作可以组合，但目标不同。把二进制内容转成 Base64 这样的文本表示，并不会自然得到保密能力，体积也通常不会因此缩小。看到“已经编码”时，不能直接理解为“已经加密”。

## 为什么容量数字有时对不上

`kB`、`MB` 等十进制单位分别以 1,000 为进位基础；`KiB`、`MiB` 等二进制单位以 1,024 为进位基础。例如 1 MiB 是 1,048,576 字节。现实界面的单位标注并不总是统一，还可能存在格式化、系统文件等额外占用。比较数字前应先确认单位。[NIST 的二进制前缀说明](https://physics.nist.gov/cuu/Units/binary.html)列出了这两套表示的区别。

理解这些约定后，再遇到文字乱码、接口内容不能解析、图片体积出乎预期等问题，就能先分清：错误可能在数据本身，也可能在解释数据所采用的规则。让 AI 修改程序之前，把文件格式、编码方式和实际样本说清楚，往往比反复描述“看起来不对”更有帮助。
