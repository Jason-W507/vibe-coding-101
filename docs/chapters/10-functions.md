# 函数、参数与作用域

一段逻辑需要反复使用，或者值得单独命名时，可以把它组织成函数。函数为代码建立了一个边界：从哪里获得输入，完成哪项工作，以及把什么结果交给调用者。

## 看清输入与返回值

```python
def remaining_pages(total, read):
    return max(total - read, 0)

result = remaining_pages(200, 48)
print(result)
```

输出 `152`。`def` 定义函数，`total` 与 `read` 是参数名称，调用时传入的 `200` 和 `48` 是本次使用的具体值。`return` 把计算结果返回给调用处。

这里选择“最少返回 0”的规则，是示例本身的设计。另一种业务也可能要求遇到超出总量的输入就报错。函数名称提供了意图，代码和约定才决定它实际允许什么。

定义函数与调用函数也不同。定义使这段逻辑可以被使用；程序执行到调用处时，才进入本次函数调用的处理过程。

## 打印不等于返回

打印把内容发送到输出通道，常见表现是在终端显示。返回值则交给调用该函数的代码，后者可以继续计算、保存或显示它。

如果一个函数只写了 `print(total - read)` 而没有写 `return`，Python 会默认返回 `None`。调用者把返回值赋给变量时拿到的就会是 `None`，常会导致“终端屏幕上有数字，但下一步计算却报 `NoneType` 错误”。函数可以同时打印和返回，也可以都不做，具体要看设计。

## 作用域决定名字在哪里起作用

```python
count = 10

def next_count(count):
    count = count + 1
    return count

print(next_count(count))
print(count)
```

输出依次是 `11` 和 `10`。函数中的参数名字 `count` 属于这次调用的局部环境。给这个局部名字重新赋值，并没有把外面的同名变量也重新绑定。

这不能推广成“函数无法改变传入的数据”。如果传入的是列表、字典等可变对象，函数在内部原地修改对象的内容（例如调用 `items.append(...)`），外部仍可能观察到变化。名称的作用范围与对象是否共享，是两个需要同时考虑的问题。

作用域规则属于具体语言。在 Python 中，普通 `if` 或 `for` 的缩进并不会像函数那样自动建立一个独立的局部作用域（而在 JavaScript 中，`let` 和 `const` 具有花括号 `{ ... }` 块级作用域）。不能仅根据代码视觉上缩进了一层，就断言里面所有名字都只能在那一层使用。相关规则见 [Python 执行模型](https://docs.python.org/3/reference/executionmodel.html#resolution-of-names)。

## 函数可以怎样影响外部

有的函数主要根据输入计算并返回结果。另一些还会写文件、发送请求、修改共享对象或更新数据库。这类对函数外部产生影响的行为，通常称为副作用。

副作用是许多软件功能所必需的。关键是让边界清楚：调用者应知道函数是否会保存东西、是否可能失败、能否重复调用，以及失败时哪些事情已经发生。

例如，“计算阅读百分比”和“把阅读记录保存到服务器”适合具有不同约定。前者关注输入和计算结果，后者还涉及通信、权限和持久保存。把所有动作隐藏在一个名字模糊的函数里，会让程序更难理解。

## 复用的价值来自清楚的边界

函数不只是为了少写几行代码。一个名字明确、输入输出清楚的函数，允许读者暂时忽略内部细节，先理解更大的流程。

当 AI 建议“封装成函数”时，可以看它是否真的形成了清楚的职责，还是只是把一大段混杂行为搬到了另一个位置。函数越长不必然越差，函数越短也不必然越好；应看这段逻辑是否围绕同一个完整问题组织，以及边界是否容易说明。

> [!TIP]
> **实战提示**：分清函数是在**终端打印（`print`）**还是向调用者**返回结果（`return`）**；如果一个函数还会修改外部列表或写文件，请让 AI 在函数名和说明里明确标出这种副作用。
