# 等待、异步与并发

软件经常需要等待：等文件读取、等网络回复、等用户操作。如果每次等待都让其他工作完全停下，界面可能失去响应，服务也难以同时处理多个请求。异步与并发讨论的，就是怎样组织这些活动。

## 三个词描述不同的事

**并发**表示多项活动在一段时间里交错推进。**并行**表示其中一些工作在同一时刻实际执行。**异步**则常用于描述一种无需把当前执行一直阻塞到操作完成、可以稍后取得结果的组织方式。

一个线程可以在等待期间切换去推进其他任务，从而实现并发；多个处理器核心也可以让工作并行。使用异步语法，并不自动意味着调用了更多 CPU 核心。

## 看两次等待怎样安排

假设有两项互不依赖的网络读取。如果先等第一项完全结束再启动第二项，两段等待会前后发生。如果先把两项都安排出去，再取得各自结果，等待就有机会重叠。

```text
依次安排：第一项 [等待……完成]  第二项 [等待……完成]
提前安排：第一项 [等待……完成]
          第二项 [等待……完成]
```

图只是概念示意。真实时间还受到服务响应、调度、连接数量和其他条件影响，不能据此保证一定节省某个精确比例的时间。

## 一个可以直接阅读的异步示例

下面的 Python 代码用短暂等待模拟两项操作，不访问网络。适用于普通脚本环境。

```python
import asyncio

async def wait_for_label(label):
    await asyncio.sleep(0.1)
    return label

async def main():
    first = asyncio.create_task(wait_for_label("第一项"))
    second = asyncio.create_task(wait_for_label("第二项"))
    print(await first, await second)

asyncio.run(main())
```

输出为 `第一项 第二项`。两项任务先被创建，之后才取得结果，因此两段 `0.1` 秒的等待可以重叠（总耗时约 `0.1` 秒，而不是依次等待的 `0.2` 秒）。输出的先后顺序由这里的打印方式组织，不能拿它直接推断两项任务内部每一步的实际调度顺序。

`await` 可以在需要等待时暂停当前协程（能够暂停并稍后恢复的函数），让事件循环（负责检查哪些等待已就绪并继续调度的循环机制）有机会推进其他工作。需要注意三个高频陷阱：① **调用 `async` 函数时若漏写 `await`**，函数体根本不会执行，而是只返回一个未执行的协程对象（Python 会提示 `RuntimeWarning: coroutine ... was never awaited`；在前端 JavaScript 中，调用 `fetch()` 等异步函数漏写 `await` 则会拿到尚未完成的 `Promise {<pending>}`）；② 在 `async` 函数里调用同步阻塞函数（如 `time.sleep()`）会卡住整个事件循环；③ 仅把纯 CPU 计算放进异步函数不会让计算变快。[Python 的协程与任务文档](https://docs.python.org/3/library/asyncio-task.html)解释了任务如何安排，[开发说明](https://docs.python.org/3/library/asyncio-dev.html#concurrency-and-multithreading)则讨论了阻塞工作对事件循环的影响。

## 工作交错以后，状态也需要协调

两项任务都读取同一个数量，再各自写回“原值加一”，最后的结果未必包含两次增加。问题不一定在算术，而在于“读、改、写”三个步骤互相穿插，这类依赖具体执行先后次序的缺陷常称为**竞态条件（race condition）**。

线程、进程、异步任务以及数据库请求，都可能涉及不同层面的协调机制。锁、队列、事务等概念分别在一定范围内帮助组织访问，不是一把能够自动解决所有情况的通用钥匙。

## 响应及时与工作完成也不同

应用可以先告诉你“正在处理”，保持界面可以操作，再在后台完成任务。此时响应及时，不代表后台工作已经成功。程序还需要报告进度、失败、取消或超时等结果。

阅读 AI 生成的异步代码时，可以沿着三件事看：任务何时被安排，结果在哪里被等待或处理，失败时谁会知道。这样比只寻找有没有 `async` 这个词，更能解释程序是否真正按预期运行。
