# 测试在检查什么

软件修改以后，需要知道重要行为是否仍符合约定。测试把一些输入、操作和预期结果组织成可重复的检查。它为判断提供证据，检查的范围由具体用例和运行条件决定。

## 先有约定，才有预期结果

假设这里选择的规则是：总页数必须是正整数，已读页数是 0 到总页数之间的整数，返回剩余页数。下面的函数按照这套规则处理；它比前面用于展示函数语法的简化例子有更严格的输入边界。

```python
def checked_remaining_pages(total, read):
    if type(total) is not int or type(read) is not int:
        raise TypeError("页数需要是整数")
    if total <= 0 or read < 0 or read > total:
        raise ValueError("页数范围不正确")
    return total - read

assert checked_remaining_pages(200, 48) == 152
assert checked_remaining_pages(200, 0) == 200
assert checked_remaining_pages(200, 200) == 0

try:
    checked_remaining_pages(200, 201)
except ValueError:
    print("超出范围的输入被拒绝")
else:
    raise AssertionError("程序应拒绝超出范围的输入")

print("四项行为检查通过")
```

运行后会看到两行提示。这些检查说明几个选定输入满足约定，并没有穷尽所有情况（在真实工程中，这类检查通常会使用 `pytest`、`Vitest`、`Jest` 等测试框架组织在 `tests/` 目录下，通过一条命令批量运行并依据退出码判断是否全部通过）。示例中的 `assert` 用于展示检查思路；真实应用不能把可被运行选项（如 `python -O`）关闭的断言当成唯一的业务输入验证，函数中的显式异常判断承担了这项工作（这里用 `type(total) is not int` 而非 `isinstance`，是因为在 Python 中布尔值 `True`/`False` 也是 `int` 的子类，需避免把布尔值误当成页数 `1` 或 `0`）。

## 不同层次看见不同问题

单元层面的测试关注较小的逻辑单元，例如页数计算。集成测试关注多个组成部分怎样配合，例如接口处理与数据库操作是否一致。端到端测试则从较接近用户的路径观察行为，例如填写页面并查看保存结果。

这些层次没有谁能够完全替代其他层次。单个函数正确，不代表页面提交了正确字段；一次完整流程成功，也可能没有覆盖许多函数边界。测试越接近完整环境，通常还会涉及更多运行条件和维护成本。

## 回归检查关注已有能力

修改一个问题时，可能影响原来已经正常的行为。把重要行为保留为可重复检查，可以帮助发现这种倒退，称为**回归检查（回归测试，regression testing）**。

如果修复了“超出总页数仍能保存”，就应考虑普通输入和边界输入是否仍然符合规则，而不只证明原先失败的一个例子现在改变了表现。

## 模拟与真实环境各有什么边界

测试可以用替代对象模拟网络、数据库或时间，让检查更快、更稳定，也更容易制造某些情况。但模拟对象仍然是对真实环境的一种描述，可能遗漏接口或行为细节。

如果所有测试都只与模拟数据库交互，实际数据库的约束和查询差异就可能没有被观察到。相反，完全依赖外部环境也会引入网络和服务状态等变化。应让不同检查承担合适的证据角色。

## 通过测试不能推出任何情况都正确

常规测试通过，意味着执行过的检查在相应条件下通过。输入、环境和交互的可能组合通常比已有用例更多。这个边界并不削弱测试的价值，而是提醒我们把结论说准确。[Dijkstra 的《The Humble Programmer》](https://www.cs.utexas.edu/~EWD/transcriptions/EWD03xx/EWD340.html)讨论了测试与程序正确性之间的关系。

AI 可以同时生成实现和测试，但如果两者采用了同一个错误假设，它们也可能一致地通过。一个更稳妥的做法是：**先由人根据需求确认好输入与期望输出的测试用例，再让 AI 编写实现代码**；当 AI 修改已有测试文件（例如删掉断言、加上 `skip` 跳过测试，或把期望值改成错误的实际输出）时，必须重点人工审查。预期行为仍要从需求和规则得到支持，不能仅由被测实现自己决定。

阅读“已通过测试”的说明时，可以看具体检查了什么、实际在哪个环境运行，以及还没有覆盖哪些与当前改动相关的情况。这样，测试结果才成为有范围、有含义的证据。
