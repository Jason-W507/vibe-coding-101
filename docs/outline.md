# Vibe Coding 101：目录与阅读路线

本教程帮助非计算机专业读者理解现代计算机、程序设计和软件开发的基本概念及其联系，可以从[完整目录](../README.md)开始顺序阅读，也可以通过[常见问题索引](questions.md)、[常见术语速查表](glossary.md)或[实战防坑清单](checklist.md)直接进入相关篇目。本页记录课程结构的编排脉络。

## 编排与阅读方式

默认顺序为：**全景导览 → 计算机怎样运行软件 → 程序怎样表达逻辑 → 数据结构与算法 → 网络与 Web → 软件开发与维护 → AI 编程**。

全书包含一篇导览和六部分、三十五篇专题。每篇围绕一个完整的问题组织，前置概念和关联链接用于方便补读，读者也可以直接通过常见问题索引进入需要的专题。

数据编码、指令执行、内存管理等底层内容安排在计算机基础部分展开。每篇先说明它解决什么问题，再解释运行机制。

## 导览：先认清自己在看什么

| 专题 | 核心问题 | 辅助示例候选 |
| --- | --- | --- |
| 00. 一张图看懂计算机、程序与软件开发 | 硬件、操作系统、程序、软件、网站、开发工具与 AI 编程之间是什么关系？桌面软件、手机应用、网站和脚本有哪些共同点？教程怎样读？ | 一张全景概念图；用常见应用标出相关层次。 |

导览只建立方位感和必要的短定义，不提前完整讲解后续原理。

## 第一部分：计算机怎样运行软件

**承接导览，建立数据、存储和执行的基本认识。** 本部分开头先给出各组成部分的职责；随后展开原理，避免一开始只列硬件名词。

| 专题 | 核心问题 | 辅助示例候选 |
| --- | --- | --- |
| 01. CPU、内存、磁盘与操作系统 | 各部分分别负责什么？安装了软件和正在运行软件有什么区别？ | 软件从启动到关闭的过程。 |
| 02. 数字、文字、图片怎样成为数据 | 比特、字节、二进制与编码是什么？为什么文字、图片和文件大小都能用数字描述？ | 字符与字节对照；一小块像素的表示。 |
| 03. 文件、目录、路径与权限 | 文件放在哪里、怎样找到它？扩展名、相对路径、绝对路径和权限分别表示什么？ | 小型目录树与两种路径写法。 |
| 04. 程序、指令与进程 | 磁盘上的程序怎样成为执行中的活动？指令、进程和线程分别处于什么层次？ | 程序文件、运行中的进程与指令执行流程对照。 |
| 05. 内存里的数据去了哪里 | 内存地址、分配、释放、栈、堆和虚拟内存解决什么问题？ | 一份数据从创建到使用、释放的过程图。 |
| 06. 终端、命令与运行环境 | 图形界面和命令行怎样使用系统？工作目录、参数、环境变量与 PATH 为什么影响运行？ | 一条简单命令与文件、工作目录和环境的关系图。 |

**先修与回链：** 数据表示先于内存内容的解释；文件与路径先于工作目录；程序与进程先于更具体的运行环境。编程语言如何运行在第二部分展开。

## 第二部分：程序怎样表达逻辑

**利用已建立的数据和执行概念解释程序。** 以短代码说明通用概念，帮助读者读懂逻辑、理解文件职责及小幅改动。

| 专题 | 核心问题 | 辅助示例候选 |
| --- | --- | --- |
| 07. 编程语言与程序的运行 | 源代码、编译、解释和运行时分别是什么？为什么不同语言有不同的运行方式？ | 几条简化的“源代码到运行结果”路径，注明简化之处。 |
| 08. 变量、值、类型与表达式 | 程序怎样表示和处理信息？数字、文字、布尔值、空值和类型有什么意义？ | 数值计算、字符串处理及类型不匹配的短代码。 |
| 09. 条件与循环 | 程序怎样作选择和重复操作？执行顺序如何影响结果？ | 判断和遍历的短代码，配执行路径。 |
| 10. 函数、参数与作用域 | 怎样给一段逻辑命名并复用？输入、输出和变量可见范围是什么？ | 一项简单操作的函数，逐项标出输入、返回值与局部变量。 |
| 11. 模块、接口与程序组织 | 代码为什么分文件？模块、接口和对象怎样帮助理解职责与边界？ | 从小段代码拆出两个职责清楚的模块。 |
| 12. 错误与异常 | 语法错误、运行错误和逻辑错误有什么区别？异常、调用关系和错误信息怎样联系？ | 几种简短错误信息与对应的代码位置。 |
| 13. 等待、异步与并发 | 程序等待一次操作时会发生什么？异步、并发与并行分别描述什么？ | 几项操作的时间线；连接到进程和线程的回链。 |

**先修与回链：** 变量和表达式先于控制流程，控制流程先于函数示例，函数先于模块间调用；异步示例使用前面出现过的函数和执行概念。调试工具的使用思路留到软件开发部分。

## 第三部分：组织数据与解决问题

**建立数据结构和算法的基本直觉。** 使用少量数据与图解，说明用途和开销。

| 专题 | 核心问题 | 辅助示例候选 |
| --- | --- | --- |
| 14. 常见数据结构各有什么用 | 列表、映射、集合、栈、队列和树分别方便表示什么关系？ | 同一组少量数据用不同结构组织。 |
| 15. 算法与时间、空间开销 | 算法是什么？查找和排序为什么有不同做法？输入变多后工作量怎样变化？ | 逐个查找与缩小范围的对照；工作量示意图。 |

**先修与回链：** 示例依赖变量、条件、循环及函数。需要区分表示方式、算法思路与具体语言提供的容器；不采用刷题式编排。

## 第四部分：一次 Web 操作经历了什么

**从找到服务到页面变化，逐步拼出完整过程。** 各专题使用简单场景辅助讲解，在本部分结尾把数据和请求的流动串起来。

| 专题 | 核心问题 | 辅助示例候选 |
| --- | --- | --- |
| 16. 设备怎样在网络中找到彼此 | 网络、互联网、IP、端口、域名和 DNS 是什么？localhost 表示什么？ | 从网址到目标服务的寻址过程图。 |
| 17. 请求、响应与 HTTP | 浏览器发送什么、收到什么？HTTPS、状态码、请求头和消息体分别是什么？ | 一对经过简化的请求与响应。 |
| 18. 浏览器、页面与前端 | 页面结构、样式、交互和渲染怎样配合？执行代码与显示内容之间是什么关系？ | 小页面中的结构、样式和交互职责对照。 |
| 19. 服务器、后端与 API | 服务端程序怎样接收请求并返回结果？路由、接口、输入校验和业务逻辑各负责什么？ | 一次查询或保存操作的时序图。 |
| 20. 数据保存、数据库与 SQL | 运行中的数据与长期保存的数据有什么区别？表、记录、键和查询是什么？ | 一张小表与几条查询示意。 |
| 21. 索引与事务 | 如何理解查找数据的效率，以及一组更新需要一起成功或失败的情境？ | 少量记录的查找对照；两步数据更新的过程图。 |
| 22. 登录、状态与访问权限 | 网站怎样识别请求者？Cookie、会话、令牌、认证和授权是什么关系？ | 登录前后的请求与状态变化。 |
| 23. 把一次操作串起来 | 从点击按钮到数据保存再到界面更新，各部分怎样协作？故障可能出现在哪里？ | 一张完整流程图，标出数据、请求及错误的可能位置。 |

**先修与回链：** 网络寻址先于请求流程，请求流程先于前后端分工，表与查询先于索引和事务，登录状态建立在请求和数据的认识上。综合流程是一段讲解和图示。

## 第五部分：软件如何被开发与维护

**连接已经认识的代码与系统，解释现代开发流程。** 这一部分覆盖需求到维护的全貌，帮助读者理解工具和步骤为何存在。

| 专题 | 核心问题 | 辅助示例候选 |
| --- | --- | --- |
| 24. 从需求到软件设计 | 人的需求怎样变成程序处理的规则？职责、接口、边界和设计取舍是什么？ | 一段日常需求对应几条规则和职责图。 |
| 25. 读懂一个代码项目的目录 | 源码、配置、资源、依赖与生成文件各是什么？哪些文件通常直接表达程序逻辑？ | 中性的项目目录，标注各类文件职责。 |
| 26. 依赖、包管理、库与框架 | 为什么代码会依赖其他代码？库、框架、包管理与版本解决什么问题？ | 简化的依赖关系图和版本变化情境。 |
| 27. Git、版本与协作 | 修改怎样被记录、比较、讨论和合并？提交、分支、仓库、冲突和代码审查是什么？ | 一段带说明的版本历史与小段改动差异。 |
| 28. 调试、日志与问题定位 | 出现问题时可以从哪里获得证据？日志、调用信息和断点各说明什么？ | 小故障的观察、定位和解释过程。 |
| 29. 测试在检查什么 | 开发者怎样检查程序行为？不同层次的测试和回归检查分别有什么用途？ | 一项软件行为的输入、预期结果与检查示意。 |
| 30. 构建、发布与运行环境 | 源码怎样变成运行中的软件？开发与生产、配置、密钥、构建产物及持续集成如何连接？ | 从修改源码到发布运行的流程图。 |
| 31. 维护、可靠性与基本安全 | 上线后为什么还要更新、备份、观察运行情况和处理权限？工程中的常见取舍是什么？ | 一次更新或故障的简短情境。 |

**先修与回链：** 文件和模块的认识支撑项目目录，语言运行方式支撑依赖与构建，错误及请求流程支撑调试，函数和接口支撑测试示意。这里的测试指软件测试。

## 第六部分：理解 AI 编程

**在完整的基础认识上，解释人与 AI 怎样协作。** 本部分集中讨论如何借助已经建立的软件知识与 AI 配合开发、审查修改并识别风险。

| 专题 | 核心问题 | 辅助示例候选 |
| --- | --- | --- |
| 32. AI 编程与 Vibe Coding | 这些说法有哪些用法？AI 可以参与哪些开发活动，哪些事情需要人的判断？ | 解释、生成、修改、检查代码等协作场景；术语说明采用核验过的来源。 |
| 33. 模型、上下文与开发工具 | 模型、聊天界面、编程助手与调用工具的智能体各处于什么位置？上下文怎样影响回答？ | 同一小问题在缺少和提供相关文件信息时的对照。 |
| 34. 与 AI 讨论需求和修改 | 怎样提供相关背景、说明边界并理解改动？如何阅读计划、代码差异和运行结果？ | 短对话与对应的小范围修改说明。 |
| 35. 理解 AI 的局限与常见误区 | 为什么看似合理的回答仍可能不正确？如何用已了解的软件知识定位疑问？ | 常见错误归因与对应的概念回链。 |

**先修与回链：** 主要使用需求、文件职责、版本差异、运行环境和调试等概念。工具类别及协作原则先于具体操作示例，具体产品的界面和版本信息在示例选型时核实。
